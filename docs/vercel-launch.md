# Vercel frontend launch for mkrting.com

Research checked 23 September 2026. This project publishes **static HTML**, generated by Python from reviewed article JSON. Vercel runs the build and serves `dist/` from its CDN. Collection, scraping/lead discovery, Gemini calls, SQLite and PR creation continue on the Linux laptop. Do not add Gemini, GitHub or Meta tokens to Vercel: the frontend does not need them.

## What is already configured

- `vercel.json` sets the **Other** framework preset, skips package installation, runs `python3 tools/build_site.py && python3 tools/check_site.py`, serves `dist/`, and redirects slashless page URLs to the canonical trailing-slash form. Vercel [documents these build and output overrides](https://vercel.com/docs/builds/configure-a-build) and [trailing-slash redirects](https://vercel.com/docs/project-configuration/vercel-json).
- Every article and guide is complete HTML at a stable URL. A crawler can read the title, body, links, source list and JSON-LD without executing JavaScript. Google [explains why HTML in the response is straightforward to crawl](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).
- The builder emits unique titles, descriptions, canonical links, Open Graph tags, Article and Breadcrumb structured data, `robots.txt`, `sitemap.xml`, and RSS. The site checker compares sitemap URLs with page canonicals and checks internal links.
- The public canonical origin is `https://mkrting.com`. The builder normalizes a legacy `SITE_URL=https://www.mkrting.com` setting to the apex domain, but set Vercel's `SITE_URL` to `https://mkrting.com` to avoid confusion. A preview URL may display a canonical pointing at the production domain; do not submit a preview URL to search engines.
- `dist/`, local secrets and the collection database are excluded from the Vercel upload context. Only `dist/` is the served output. Static hosting does not run the laptop's background process.

## One-time account and domain setup

1. Complete the [editorial review](launch-story-review.md) before making the first production deployment. Then create the GitHub repository, push the approved project, and import it into a Vercel project. Set the production branch to `main`. Vercel [deploys connected Git changes automatically](https://vercel.com/docs/builds). The old GitHub Pages workflow has been removed; the GitHub Action now checks content and build quality only.
2. Let `vercel.json` supply the project build settings. Confirm the first deployment's Build Command, Output Directory (`dist`) and Framework Preset (`Other`) in Vercel's build settings. No Node package or server-side function is needed to render the public pages.
3. Add `mkrting.com` and `www.mkrting.com` in Project Settings → Domains. Use the **specific DNS records shown by Vercel's domain inspection** at your registrar; do not assume a generic IP address. Configure `www.mkrting.com` to redirect to `mkrting.com`, since the generated canonical URLs use the apex. Vercel [recommends explicitly redirecting one of the two hosts](https://vercel.com/docs/domains/set-up-custom-domain). Wait for domain verification and HTTPS to work.
4. For later stories, review each draft PR and merge only after editorial approval. Once `main` is connected, a merge becomes a production deployment.

The Vercel CLI is installed **locally** at `.local/vercel-cli/node_modules/.bin/vercel` (version checked: 59.25.4). It is optional for normal Git-driven publishing. After you have a Vercel account, use that command with `login` or `link` if you prefer terminal setup; these steps need your own account session and are not completed here. Vercel's [CLI reference](https://vercel.com/docs/cli) documents the account login and linking flow.

## Vercel Analytics and Speed Insights

Search Console measures search visibility; Vercel Web Analytics measures site visits; Speed Insights measures actual visitor performance. None of these directly improves ranking. [Vercel Web Analytics setup](https://vercel.com/docs/analytics/quickstart) and [Speed Insights setup](https://vercel.com/docs/speed-insights/quickstart) currently use a **project-specific script path** for plain HTML sites. The site builder is ready to insert them into every page without a JavaScript framework:

1. Enable Web Analytics and, if desired, Speed Insights in the Vercel project dashboard. Review plan limits before enabling paid observability products.
2. Get the script paths Vercel gives this project. Set `VERCEL_WEB_ANALYTICS_SCRIPT_PATH` and `VERCEL_SPEED_INSIGHTS_SCRIPT_PATH` as **Production build environment variables**, each in the form `/<project-specific-path>/script.js`. They are paths, not API keys. Do not paste the literal placeholder `<unique-path>`.
3. Redeploy. Inspect the HTML response for the script tags, confirm each script returns 200, and check the dashboard after visits. If a product is not enabled or its path is unavailable, leave its variable unset; the generated HTML remains tracker-free.
4. Keep Search Console as the source for impressions, queries, indexed pages and Google-selected canonical URLs. Analytics page views do not equal search traffic.

## Live SEO acceptance checks

After the custom domain is working, check the **HTTP response**, not only what a browser shows:

1. `https://mkrting.com/`, one article and one guide return 200 with visible text. `https://www.mkrting.com/` permanently redirects to the apex. A slashless article URL redirects to its slash-terminated canonical. Missing pages return 404 rather than a 200 homepage.
2. On each important page, verify one `<title>`, one meta description, one visible `<h1>`, a self-referencing canonical at `https://mkrting.com/.../`, relevant internal links and the source links. Confirm the page is not blocked by a `noindex` response header or an access prompt.
3. `https://mkrting.com/robots.txt` exposes `https://mkrting.com/sitemap.xml`. The sitemap lists only canonical public pages; each listed URL responds successfully. Confirm that Contact, Privacy and Terms are present and that the footer email and LinkedIn link are correct. Vercel [sets `X-Robots-Tag: noindex` on preview deployments by default](https://vercel.com/docs/deployment-protection#preview-deployment-protection); verify production separately, especially if assigning a custom domain to a non-production branch.
4. Verify the domain property in Google Search Console and Bing Webmaster Tools. Submit the sitemap and inspect the homepage, the guide, and at least two articles. Use Google's Rich Results Test to check structured data against the live HTML. Neither schema nor a sitemap guarantees indexing or ranking.
5. Check mobile and desktop with PageSpeed Insights after launch. Observe real LCP, INP and CLS in Search Console and, if enabled, Vercel Speed Insights. The initial frontend has no content-rendering JavaScript, but field data is unavailable until real traffic arrives.
6. Monitor Search Console query and page reports. Improve articles that earn impressions but do not answer the visible query well. Build original diagrams, reporting, comparisons and relevant citations; avoid duplicate keyword pages or purchased links.

## Limits and follow-up

- A Vercel deployment does not run the laptop's recurring collector. If the laptop is offline, no new draft PRs appear. Already published static pages remain online.
- The site has no live Vercel deployment, verified domain or Search Console property in this workspace, so DNS, status codes, analytics collection and indexing must be checked after the account is connected.
- Do not add long-lived immutable browser caching to `style.css` or article images unless filenames become content-hashed; the current filenames can change on later deployments.
- Vercel hosting and good technical SEO make pages accessible. They do not guarantee that a new domain ranks for broad searches like “marketing” or “branding.”
